Flow-based confidentiality: the design in four figures (as first built; revised 2026-10-04)

Revised by Plan 13 D8 (12), 2026-10-04. These figures show Plan 10 as first built, when the consumer table made psql, aws, gh, git and others default readers. That rule is inverted: raw bytes go only to a vetted reader (ssh, ssh-add) or to a program whose entry carries the human's word, prints: nothing; every other program gets the twin. A printer (git, curl, scp, psql, pg_restore) or a program that runs code (bash, node, python3) admits nothing, so the panels that show them reading raw (the two tables, Figures 3b, 3c, 3e and 4b, and rows 4 to 6 of Figure 4e) describe the old behavior. The current model is drawn in reader-set-labels.html and stated in confidentiality-plan-13-reader-set-labels.md §3 D8.
